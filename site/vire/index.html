A new primary coding language

Write Vire. Compile Vire. Run native.

Vire is a small, readable language whose compiler is written in Vire. On Windows, that compiler emits a PE image with no outside C toolchain in the emit path. Guests run in a sandbox. Capabilities are enforced by the runtime today; a can declaration line is not in the grammar yet.

Get started View the repository

The sample below is the real file examples/hello.vire. CI interprets it and compiles it to a Windows PE.

examples/hello.vire 
~ Hero sample: a complete Vire program.
define greet with who
  return "hello, " + who
end

define main
  say greet with "vire"
end

Why Vire

These are properties of the tree in this repository, not slogans.

Self-hosting compiler

compile-native.vire is Vire. CI on Windows builds gen1, then gen1 compiles the compiler to gen2, and the hex files match. That job is native-selfhost-windows.

Native output, no extra compiler

The emit path writes a Windows x64 PE from Vire sources. It does not shell out to cl, gcc, or rustc. The bootstrap host is still the .NET 10 runner in this repo.

Capability-shaped sandbox

Guests cannot wander the disk. read/write stay under data/ and site/. Native images import a fixed allowlist (no LoadLibraryA, no CreateProcess). There is no can listen syntax yet — policy is implicit.

Sandboxed guests

Compiled programs run with a 32 MB arena, a 100,000 item list cap, and a step budget. Path, junction, and hardlink checks live in CI (native-windows, native-sec-emu-check.sh).

Gradual types, honestly

Values are dynamic: number, text, list, map, bool, none. There are no type annotations in the grammar today. Host kind and map-shaped schema checks exist as libraries, not as a type checker.

Networking on the native path

HTTP listen (loopback), loopback TCP connect/send/recv, and a Postgres client are landing. TLS for that client is still in progress. See native-net.yml.

A short tour

Programs from site/vire/examples/. Each one is interpreted and compiled in site-vire.yml.

count.vire → 1..5
~ Tour: while loops and integer arithmetic.
define main
  let n be 1
  while n <= 5
    say n
    let n be n + 1
  end
end
defs.vire → 12, 10, 0
~ Tour: definitions, return, nested if.
define area with w, h
  return w * h
end

define clamp with n, low, high
  if n < low
    return low
  end
  if n > high
    return high
  end
  return n
end

define main
  say area with 3, 4
  say clamp with 20, 0, 10
  let low be 0 - 4
  say clamp with low, 0, 10
end
control.vire → two, 1, 3
~ Tour: else if, for, skip.
define main
  let n be 2
  if n == 1
    say "one"
  else if n == 2
    say "two"
  else
    say "other"
  end
  for item in [1, 2, 3]
    if item == 2
      skip
    end
    say item
  end
end
lists.vire
~ Tour: lists, maps, length, at.
define main
  let nums be [9, 2, 3]
  push with nums, 4
  say nums at 0
  say length with nums
  let person be {"name": "ada", "year": 1815}
  say person at "name"
  say has with person, "year"
end
text.vire
~ Tour: text builtins the native compiler emits.
define main
  let word be "Vire"
  say lower with word
  say begins with word, "Vi"
  say ends with word, "re"
  say replace with word, "i", "y"
  say find with word, "r"
  say word at 0
end
try-miss.vire → caught, 12
~ Tour: try / miss on a failing conversion.
define main
  try
    say number with "nope"
  miss problem
    say "caught"
  end
  say number with "12"
end

Getting started

You need the .NET 10 SDK. Binaries are not stored in git. These commands are the ones this repo’s CI uses.

Build the host runner

From the repository root:

dotnet build vire.csproj -c Release

Run a program (interpreter)

dotnet exec bin/Release/net10.0/vire.dll site/vire/examples/hello.vire

Stdout is hello, vire.

Compile to a Windows PE

On Windows, after the same build. Paths use forward slashes. The guest file must be readable by the sandbox (data/ is the usual staging folder):

dotnet exec bin/Release/net10.0/vire.dll --compiler compile-native.vire data/guest-hello.vire data/guest-hello.hex

Turn the hex into an .exe (two hex digits per byte) and run it. CI does this in tools/native-selfhost-handoff.ps1.

Roadmap

Marked as the tree stands, not as a launch plan.

  • now
    Windows PE self-host. gen1 = gen2 is the native-compiler proof.
  • now
    Loopback HTTP listen and TCP. Bind stays on 127.0.0.1 unless a documented env gate says otherwise.
  • in progress
    Postgres client TLS / SCRAM. Loopback trust/cleartext is what CI proves. SCRAM and TLS are residuals under the 5M step cap.
  • in progress
    Linux ELF. Not emitted. Unicorn emulation is used in some checks; it is not a Linux product binary.
  • in progress
    can capability lines. Not parsed. Security is sandbox + import allowlist + caps.
  • in progress
    Optional type annotations. Not in the grammar. Values stay dynamic.
  • out
    Public internet hardening, TLS server, package index, driver loading, FCG testnet. Not this site, not this PR.
